# 课务台（Laosu Workbench）

> 一个把「排课、事务、日历」收进同一界面的 HanaAgent 全屏插件。
> **界面只读，所有变更交给 AI 执行** —— 这是它最核心的设计取舍。

[![topic](https://img.shields.io/badge/topic-oh--plugin-4D6BFE)](https://github.com/topics/oh-plugin)

---

## 这是什么

课务台是运行在 [HanaAgent](https://github.com/topics/oh-plugin) 内的全屏工作台插件，用来管理**课程安排**和**日常事务**。

它的定位比较特别：**前端只负责展示，不负责操作。**

你在界面上看到课表、待办、冲突提醒，但想调课、取消、加课——不是去点某个「编辑」按钮，而是**唤起 AI，让 AI 去执行**。所有真实写入统一走 AI 入口。

这样做的好处：
- 界面永远不会因为误点而改坏数据
- 所有变更都有预演（dry-run）和审计记录
- 复杂操作可以直接说人话（「把周三的课挪到周五，冲突就换下周」）

---

## 核心设计

### 1. 只读界面 + AI 执行

界面上每张卡片只有两个按钮：
- **确认 / 不确认** —— 处理需要你拍板的事
- **调** —— 点开直接唤起带该课上下文的 AI 对话框

取消、改期、补记这类操作**全部收进详情和 AI**，不在主界面暴露。

### 2. 所有写入必须预演

这是硬约束，不是建议：

| 规则 | 说明 |
|---|---|
| 不直接读写 SQLite | 只通过 Python 脚本的 agent 契约 |
| 排课只调 `schedule.py agent` | 事务只调 `affairs.py agent` |
| 调课用 `move` | 不用 `cancel + add`，避免丢失关联 |
| **所有真实写入先 dry-run** | 预演令牌 15 分钟有效、一次性使用 |
| 写入后回读 | 确认真的写进去了 |
| 事务写入带 `--request-id` | 保证幂等 |
| 全量审计 | 预演和提交都记进插件私有审计日志 |

### 3. 冲突自动检测

刷新后统一检查三类冲突：课程×课程、课程×事务、事务×事务。

进行中的事务若缺结束时间，会明确提示「校验不完整」，而不是默默算错。

### 4. 外部改动自动感知

每 45 秒探测一次课表/事务库文件变化，变了就静默全量刷新。
**其他 AI 会话的修改会自动带回界面** —— 适合多个 Agent 同时干活的场景。

## 界面结构

主导航三页：

- **总览** —— 三层：下一节课（现在做什么）→ 行动中心（欠什么决定）→ 周/月视图（安排全貌）
- **筹备** —— 试排空档、驾驶舱
- **事务** —— 待处理 / 已安排 / 已完成·已取消，列表与日历双视图

### 两条队列互斥

- **待处理**：只收需要人来决定的事（课程复核、过期未标记、真实冲突），按冲突 → 过期 → 复核排序
- **建议处理**：只收系统级优化建议（日历差异等），可折叠

同一事务只出现一次，不会重复打扰。

## 技术栈

- **运行环境**：HanaAgent 插件（`@hana/plugin-runtime` / `plugin-sdk` / `plugin-components`）
- **前端**：React 19 + Vite
- **后端**：Node.js（≥ 22.6.0）
- **数据层**：Python 3 脚本（排课 / 事务 / 日历同步）

### 与后端系统的契约

课务台**不直接碰数据库**，全部通过 Python 脚本的 agent 接口：

| 能力 | 脚本 | 契约要求 |
|---|---|---|
| 排课 | `schedule.py agent` | schema ≥ 7（contract v2） |
| 事务 | `affairs.py agent` | 带 writer 锁校验 |
| 飞书日历同步 | `sync_to_calendar.py` | 固定使用 `--prune` |

## 安装与配置

### 前置条件

- HanaAgent ≥ 0.333.0
- Node.js ≥ 22.6.0
- Python 3
- 三个后端脚本（排课 / 事务 / 日历同步）

### 路径配置

默认路径如下，**都可通过环境变量覆盖**：

| 环境变量 | 默认路径 |
|---|---|
| `LAOSU_SCHEDULE_SCRIPT` | `~/laosu-workspace/库管理与索引/老苏排课系统/schedule.py` |
| `LAOSU_AFFAIRS_SCRIPT` | `~/Shared/Hana主动式事务系统/affairs.py` |
| `LAOSU_CALENDAR_SYNC_SCRIPT` | `~/laosu-workspace/库管理与索引/老苏排课系统/sync_to_calendar.py` |

数据库路径同样可覆盖：`LAOSU_SCHEDULE_DB`、`LAOSU_AFFAIRS_DB`。

首次使用某个能力时会校验脚本路径，找不到就返回明确错误，不会静默失败。

### 开发

```bash
npm install
npm run verify    # 类型检查 + 语法检查 + 测试 + UI 构建
npm run release   # 一条命令发版（校验/备份/打包/部署/commit）
```

## 关于这个仓库

课务台原本为个人使用而写，有些设计带着强烈的个人习惯：

- 强调「确认/不确认」而非自由编辑
- 冲突和过期提醒很啰嗦
- 与飞书日历深度绑定

如果你要复用，**后端那三个 Python 脚本需要你自己实现** —— 课务台只认它们暴露的 agent 契约，不关心你内部怎么存数据。契约要求见上文。

## 安全契约

- 不直接读取或写入 SQLite
- 排课只调用 `schedule.py agent`
- 事务只调用 `affairs.py agent`
- 调课只使用 `move`，不使用 `cancel + add`
- 所有真实写入必须先 dry-run
- 对接 schedule schema >= 7（contract v2）：课程来源、周期范围、预留关联与单次 availability 覆盖均为结构化字段
- 新建/调课只有在具体单次时间已明确时才传 `--override-availability`，不会修改长期候选时间
- 预演令牌 15 分钟有效、一次性使用
- 正式写入后执行回读；日历同步固定使用 `--prune`
- 事务写入附带 `--request-id` 幂等标识
- 写入前校验排课/事务契约版本和事务 writer 锁
- 预演与提交记录到插件私有审计日志
