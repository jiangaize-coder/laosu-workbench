# 课务台

当前版本：v1.1.0

HanaAgent 全屏插件，用一个入口查看并操作老苏的排课、事务、提醒和飞书日历看板。显示名为「课务台」，内部插件 ID 保持不变。

## 当前能力

- 「课务台」全屏页面，三项主导航保持居中
- AI 操作使用右侧抽屉，保留原页面上下文；系统状态保留为二级入口
- 统一工作台视觉语言：采用无边线模块，以底色、留白和轻阴影区分层级
- 放大顶部三项主导航，强化主要切换入口
- 重新平衡主内容宽度、左右栏比例、卡片高度和模块间距
- 移除顶部重复品牌展示，保留导航与功能入口
- 顶栏左侧留空，主导航保持居中
- 总览、筹备、事务和详情共用同一套无边线颜色语法：绿色表示已确认/已完成，琥珀色表示待确认/待处理，红色表示错误/硬阻塞；临时身份以蓝色小圆点叠加，不覆盖状态色
- 筹备页使用结构化排课数据，按“周视图→资料准备→模板体检→课程预留→正式落课”形成闭环；周视图分临时预留与正式固定两层，窄窗口自动切换为每页三天并提供视图翻页按钮
- 卡片统一遵循“指向谁就原地处理谁”：待落课显示“调整时间｜确认落课”，已落课显示“调整时间｜本次不上”；触屏轻点卡片打开相同操作
- 总表课程、下一节课、普通事务、预约型事务和事务列表共用原地双动作：课程“调整时间｜本次不上”，普通事务“完成｜取消”，预约型事务“完成｜没约上”
- 事务页将“已安排”和“已完成／已取消”分区展示：进行中记录在前，完成历史在后并降低色度
- 系统状态覆盖事务、排课、学生、通勤和后续课程读取链路；写入预演令牌保留失败结果，只有成功提交后才清理
- 筹备确认落课成功或失败后自动刷新筹备数据，提交中的预演不会被内部重复检查误判；提交中保留可提交标记，避免状态机自我阻塞
- 课程主提交与飞书日历同步分层判定：快速连续落课时同步串行重试，日历锁竞争不再把已写入课程误报为失败
- 页面接口对非 2xx、非 JSON 和结构缺失统一报可读错误；渲染异常由 ErrorBoundary 隔离，不再整页白屏
- 兼容 Hana 0.450.0 静态资源鉴权：页面短期 token 仅用于同插件 CSS/JS，业务 XHR 继续走 `hana.api.fetch`
- 总览、预演和 AI 请求均有最新请求门，旧响应不能覆盖新范围或新表单
- 手动刷新强制绕过快照；快照具备并发合并与 epoch 失效，旧读取不能回写新缓存
- 中断的 committing 预演在启动时恢复为锁定失败记录；审计与令牌收尾故障不再反向误报主写入结果
- 日历同步使用 generation 队列，首次失败也会消费执行中新增的同步请求
- 总览、筹备与 AI 统一使用上海时区 04:00 日界线
- 确认落课只等待预演、写入与本地验证；飞书同步持久化后台执行，全端数据静默刷新并先在当前卡片即时显示已落课
- 已完成或已取消对象不再显示写操作；加载、失败和硬约束在原对象附近反馈，禁用原因不依赖系统黑色 title 提示
- 周视图七列按窗口比例自适应铺满；窄屏保留无痕横向滑动，不显示系统滚动条
- 周/月视图只用颜色区分课程与事务，不再设置独立事务栏；同一时刻冲突自动并排
- 学生缺口支持就地设置片区、长期候选时间、预留课程和补录通勤；已有具体单日预留时不再误判为缺时间
- 全局字号、行高和密集信息区域已重新分级；窄窗口会放大正文、控件和时间卡片，避免缩窄后难以阅读
- 顶栏三项主视图是唯一一级导航；统计卡只展示数据，不再重复跳页
- 系统状态、日期详情和条目详情统一使用右侧抽屉及返回键
- 总览待办支持快捷完成与“没约上”，移除重复的跨页入口
- 实时读取 `schedule.py agent` 和 `affairs.py agent`
- Agent 工具：读取看板、预演变更、提交一次性预演令牌
- 课程行一键带入调课预演；事务行快捷带入完成/取消/重试推进
- 记住上次标签与时间范围，显示最后更新时间
- 下一节课卡片、课间通勤时长与最晚出发时间；首节课明确提示缺少固定起点数据
- 新建课程、新建事务均走 dry-run 预演
- 今日课程结束后可一键预演“今日课程已上完”，确认后写入本地课表、导出工作簿并同步飞书日历
- AI 抽屉默认是自然语言工作台：直接说学生和目标，系统追问、生成预演，再进入确认链路
- 执行完成后原路返回；抽屉支持统一返回键、浏览器返回、焦点闭环和草稿保持
- 各标签记住独立滚动位置；时间范围切换提供加载反馈和人性化日期
- 精确表单保留为兜底能力，打开型动作统一使用省略号提示后续确认
- AI 支持新建、调课、取消、预留、事务处理与日历同步
- “筹备”视图将采集、预留、片区和可用时间结构化展示，并保留底层文本证据
- 筹备文本解析配有固定样本测试和失败回退提示
- 支持预留新增/确认/取消；出游、重复课程和老师冲突继续硬校验，通勤只在排具体时间时询问并展示提示，不再锁定落课；失败反馈不再覆盖课程卡片
- 多项调课进入 schedule plan，顺序预演、数据库版本校验、备份、原子提交、导出和日历同步
- 调课、事务完成/取消/重试推进、飞书日历同步
- 事务“没约上”一键完成后台预演、提交、回读和刷新，不再跳转二次确认
- 排课与事务操作统一提供点击反馈、处理中状态和原地结果；跳转型操作明确提示尚未执行
- 今日时间轴右上角提供“全部上完”，每节待上课程提供“没上”，均走后台预演、提交、回读与同步
- 聊天 WebView 卡片与全屏页面联动

## 安全契约

- 不直接读取或写入 SQLite
- 排课只调用 `schedule.py agent`
- 事务只调用 `affairs.py agent`
- 调课只使用 `move`，不使用 `cancel + add`
- 所有真实写入必须先 dry-run
- 对接 schedule schema >= 7（contract v2）：课程来源、周期范围、预留关联与单次 availability 覆盖均为结构化字段
- 新建/调课只有在具体单次时间已明确时才传 `--override-availability`，不会修改长期候选时间
- 预演令牌 15 分钟有效、一次性使用
- 正式写入后执行回读；日历同步固定使用 `--prune`
- 事务写入附带 `--request-id` 幂等标识
- 写入前校验排课/事务契约版本和事务 writer 锁
- 预演与提交记录到插件私有审计日志
